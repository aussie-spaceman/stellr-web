## Blast radius

**No runtime code.** The diff is six files, all under `docs/` or
`.claude/releases/`; nothing under `lib/`, `app/`, `components/`, `scripts/`,
`supabase/migrations/`, `vercel.json`, or `package.json`. The deployment this
merge triggers is a rebuild of unchanged source.

- **Migrations:** none in the diff. `db:status --prod` still reports the two
  10 Sept grade migrations as `PENDING` by filename; they are applied, and this
  was confirmed **by content** rather than by the annotation —
  `grade_type` carries `grade_6, grade_7, grade_8` immediately before
  `grade_9`, and `promote_grades()` handles `grade_6`. Their ledger rows exist
  under the MCP apply-time timestamps `20260910230533` / `20260910230740`
  (TRACKER 4.8). **Do not re-apply them** — that has happened once already.
- **Crons:** no `vercel.json` change.
- **Webhook contracts / outbound mail:** unchanged.
- **Env vars — the one substantive change, and it is configuration, not code.**
  `LINKEDIN_ORGANIZATION_ID=66274777` was added to the `stellr-web` Production
  environment on 22 Sept (value confirmed by David from the Page admin URL).
  Vercel bakes env vars in at build time, so the currently-serving deployment
  (`b9418ad`) was built without it. **This promotion's deployment is the first
  to carry it.**
  - Effect: `linkedInAddToProfileUrl()` switches from
    `organizationName=Stellr Education` to `organizationId=66274777`, which is
    what attaches the Stellr Page logo to a member's Licenses & certifications
    entry and auto-tags the Page when they share.
  - Failure mode if the ID is wrong: entries name a *different* organisation.
    `Stellr`, `STELR` and `Stellar Education` are separate LinkedIn pages. The
    builder validates only that the value is numeric (`/^\d+$/`), so a wrong
    number fails silently. Entries members have already added do **not** update
    when the variable is corrected.
  - Not set on the `stellr-web-dev` project — dev deployments keep exercising
    the `organizationName` fallback, deliberately.
- **`docs/checkr-test-seed.sql`** is a manually-run test fixture, not a
  migration; nothing applies it automatically. Its "PII" is Checkr's documented
  sandbox identities, not real people.
