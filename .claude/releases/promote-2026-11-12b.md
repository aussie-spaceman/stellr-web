- **Database work:** one extra indexed lookup per participant insert or date-of-birth change (the new AFTER trigger) and per first check-in (the new BEFORE trigger). Stellr rows write nothing and are never refused.
- **Five Stellr-only admin routes** (`remind`, `docusign-reissue`, guardian, `offerings`, `merch/commit`) make one extra read of the event's owner. If that read fails, they now return a retryable 503.

- **While the migration runs**, writes to participants, registrations, agreements and tenants wait (the new table's foreign keys lock them), normally for under a second and at most about 5 s per lock. The file's lock note understates this; that is a docs follow-up.
- **The promotion PR runs `tenant-db` as a failing check** (no longer `continue-on-error`). Read its step outcome before merging.
